Section 2

Security Findings

Findings are ordered by severity. Each finding includes a description, business impact, and concrete remediation steps.

HIGH AGENT-001 PowerShell Commands Executed Without an Allowlist

The agent executes any PowerShell command string received from the API without validating it against a permitted-command list. The only control is the DASHBOARD_API_KEY required to create a command.

If the API is compromised, or if an attacker obtains the DASHBOARD_API_KEY (currently exposed in the browser bundle — see DASH-001), they gain arbitrary code execution on every managed Windows endpoint. A single key compromise escalates to full fleet takeover.

Implement a command allowlist in internal/executor/executor.go. Define an enum of permitted command types (e.g., reboot, get-inventory, run-script:approved). Reject and log any payload that does not match. Consider signing command payloads with a separate key.

Location internal/executor/executor.go
HIGH AGENT-002 Vault Client Secret Stored in Plaintext Environment File

VAULT_CLIENT_SECRET is stored in a plaintext .env file on the VPS alongside the Docker containers, readable by any process running as root or any user with Docker socket access.

An attacker with VPS access can read this secret and authenticate to Vaultwarden as the API service, extracting all stored secrets: DATABASE_URL, DASHBOARD_API_KEY, all agent tokens. This is full credential compromise of the entire ecosystem.

Use Docker secrets (docker secret create) or an encrypted store. Rotate VAULT_CLIENT_SECRET immediately if VPS has had unauthorized access. Add a monitoring alert on Vaultwarden for multiple failed auth attempts.

Location .env (VPS /docker/sentineledge-agent/)
MEDIUM AGENT-003 Auto-Update Hash Fetched From Same API Without Signature Verification

The auto-update flow downloads the agent binary from GitHub Releases and compares its SHA256 against the hash returned by the /version endpoint — both the binary URL and the expected hash come from the same API.

A compromised API can serve a malicious binary alongside a matching hash. The SHA256 check passes because both values were crafted by the attacker. All agents auto-update to the malicious binary with no alert to the operator.

Sign the release binary with a private key (e.g., using minisign or cosign). Embed the corresponding public key as a constant in the agent binary at compile time. Verify the signature before executing the update.

Location internal/updater/updater.go
MEDIUM AGENT-004 No Exponential Backoff on API Communication Failures

When the API is unreachable, the agent retries at a fixed 30-second interval with no backoff or jitter logic.

During API outages, all agents retry simultaneously, creating a thundering-herd that amplifies load on the recovering API. This can extend the outage duration significantly across a large fleet.

Implement exponential backoff with jitter in internal/communicator/communicator.go. Suggested formula: wait = min(30s * 2^attempt, 300s) * rand(0.8, 1.2). Reset the backoff counter on the first successful response.

Location internal/communicator/communicator.go
LOW AGENT-005 No TLS Certificate Pinning for API Communication

The agent connects to saapi.ardepa.site using standard TLS certificate validation without pinning the specific server certificate or public key.

On a managed endpoint behind a corporate SSL inspection proxy, the proxy can intercept agent-to-API traffic using a locally-trusted certificate. An attacker with this capability could read PowerShell output and inject commands.

Pin the API certificate's public key hash in the resty client TLS config. Add a mechanism to update the pin via a signed configuration push before planned certificate renewals.

Location internal/communicator/communicator.go
LOW AGENT-006 Agent Bearer Tokens Never Expire

Tokens issued at agent registration are permanent. There is no TTL, no expiry field in the database, and no refresh mechanism.

A decommissioned or re-imaged endpoint retains a permanently valid credential. If the token leaks (e.g., from a disk image backup), it provides indefinite API access for that agent_id with no detection mechanism.

Add token_issued_at and token_expires_at fields to the Agent model. Implement a token refresh endpoint. Set a default TTL of 90 days with automatic renewal on each heartbeat if expiry is within 7 days.

Location sentineledge-api/api/app/models/agent.py · internal/agent/agent.go
